🎯 它到底干嘛的

一句话：通过 CLI + 浏览器扩展，给任何能调用 shell 的 AI Agent 接上一个「借用你真实浏览器」的自动化桥。

官方原话："Let AI agents use your real, logged-in browser without interrupting your work."

四大卖点

  • 复用真实登录态：Agent 操作你已经登录的网站，不用单独搞测试账号——这是它和 browser-use 最本质的区别。
  • 无打断并行：浏览器任务跑在独立的、可见的「Agent Window」里，你自己的浏览器照常用。
  • 支持任意 Agent：无模型/框架锁定，Cursor、Claude Code、Codex、Kimi Code…乃至 WorkBuddy 都在已适配列表里。
  • 内置人机协同：遇到验证码、登录、确认弹窗，Agent 可请求你接管，搞定后继续——而且是本地的，不用买云。

🏗️ 技术架构（三层桥接）

Agent Harness（Cursor / Claude Code / Codex / WorkBuddy…）通过 shell 调 bsk ...
↓ 本地 IPC
bsk CLI（Rust）→ bsk daemon（常驻本地进程）
↓ WebSocket · 127.0.0.1（仅本机）
BrowserSkill Extension（TypeScript / Chromium 扩展）
↓ CDP（Chromium DevTools Protocol）
Agent Window：独立可见窗口跑自动化 · User Window：你的普通标签页，仅被「借用」、用完归还

核心设计哲学：Agent 从不直接碰浏览器，全部经本地桥接。通信锁定 127.0.0.1，理论上不暴露到网络。

技术栈

Rust（CLI / daemon / protocol） TypeScript + pnpm（扩展 / UI / i18n） CDP（Chromium DevTools Protocol） 本地 IPC + WebSocket

GitHub 主语言标 TypeScript（扩展代码体量占大头），但性能敏感部分在 Rust。跨平台：macOS（Apple/Intel）、Linux（x64/ARM64）、Windows（x64）。

⚔️ 赛道定位：和 browser-use / Playwright 怎么摆

前文第二期分析过 browser-use vs Playwright，BrowserSkill 正好补齐这条线的第三块拼图——而且它 GitHub topics 直接挂了 browser-use，等于官方认领同赛道。

一句话区分：browser-use 是「AI 自己冲浪」，BrowserSkill 是「AI 借你的浏览器帮你办事」。两者不冲突，甚至能叠加——BrowserSkill 解决的是「登录态 + 不打扰」这个 browser-use 一直没优雅解决的痛点。

⚠️ 风险雷达
  • 太嫩：0.1.9 版本号，API/协议随时可能翻脸，生产环境务必锁版本。
  • 浏览器局限：官方只支持 Chrome / Edge（Chromium 系），Firefox 还在 规划中。Safari 用户暂时无缘。
  • 用户侧摩擦：依赖装浏览器扩展 + 引导加载，比纯 CLI 工具多一道门槛（不过它做了 Agent 自动安装脚本缓解）。
  • 「借真实登录态」本身就是双刃剑：设计上说隔离 Agent Window，但你把已登录的银行/邮箱标签页借出去，信任边界得自己掂量。扩展权限请求要看清楚。
  • bus factor 未知：腾讯开源项目，背后的真实维护人力不透明；issue 已积压 31 个（早期正常，但得观察响应速度）。
  • star 体量小：838 星 vs browser-use 的 10 万+，生态和社区验证远未到位。

🧭 一句话结论

它是浏览器自动化赛道里一个思路清奇的务实派：不跟 browser-use 卷「AI 自主冲浪」，而是解决「让 Agent 用真实登录态、还不打扰人」这个真实痛点，还顺手把移动设备模拟和白嫖式 human-in-loop 塞了进来。

什么时候用它：你想让 AI 替你在已登录的网站（后台、SaaS、内部系统）点来点去，又不想把浏览器让出去、不想买 browser-use 的云协同 → BrowserSkill 是正解。
什么时候别用：要写确定性 E2E 测试/接 CI → 老老实实 Playwright；要让 AI 在开放互联网自主探索 → browser-use 更成熟。
搭配姿势：BrowserSkill（借登录态办事）+ Playwright（确定性回归）混搭，探索期买灵活、量产期买可靠——和前文 browser-use 对比研究的结论一脉相承。

腾讯在 Agent 基础设施上的布局已经能看出脉络：BrowserSkill（操控浏览器）+ TencentDB-Agent-Memory（记忆中枢），一个管「手」、一个管「脑」，野心不小。值得持续跟踪。

本报告含分析观点，重要决策请自行核验时效性与真实性。
