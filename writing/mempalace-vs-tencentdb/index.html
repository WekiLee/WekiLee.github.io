MemPalace⚔️TencentDB-Agent-Memory

AI 记忆系统正面对决:草根基准卷王 vs 腾讯云团队级记忆中枢

⚡ 核心结论(先看这个)

同名"记忆",两种物种。MemPalace 是个人/单机导向的轻量记忆库:逐字存储、本地嵌入、pip 装完即用;TencentDB-Agent-Memory 是团队/多 Agent导向的重型记忆中枢:四类记忆资产 + ACL 治理面板 + 三服务 Docker 部署。

记忆哲学也相反:MemPalace 拒绝摘要(verbatim 逐字,怕丢信息),腾讯 主动蒸馏(L0→L3 分层提炼,怕爆上下文)。

一句话:一个人用选 MemPalace,一支 Agent 团队用选腾讯;但腾讯这个仓库的工程细节有几个值得警惕的疑点(见风险节)。

🧠 记忆哲学:逐字派 vs 蒸馏派

MemPalace —— 一个字都不许丢

  • Verbatim 逐字存储:不摘要、不改写,原文进"抽屉"(Drawers)
  • 记忆宫殿结构:Wings → Rooms → Closets → Drawers,Halls/Tunnels 做关联
  • AAAK 压缩:30 倍无损压缩方言,压缩但不丢信息
  • 时序知识图谱:SQLite 三元组带有效期窗口
  • 矛盾检测:抓 Agent 记错的姓名、年龄、代词

信念:摘要就是失真,检索质量靠结构和嵌入解决。

腾讯 —— 分层蒸馏,按需取用

  • L0 原始对话 → L1 原子事实 → L2 场景知识块 → L3 长期画像,逐层提炼
  • 混合检索:BM25 + 向量 + RRF 融合
  • 防爆保护:条目数/字符预算/超时三重限制,防记忆挤爆上下文
  • 按需调用:/v3/tools/call 现用现取,不全量注入
  • 四类资产:Chat Memory / Skill / Wiki / CodeGraph,均可版本化

信念:原始记录只是素材,蒸馏后的"资产"才能装备给 Agent 团队。

🏗 架构与部署:轻骑兵 vs 重装旅

维度MemPalaceTencentDB-Agent-Memory
部署形态pip/uv 一条命令,Python 库即服务;Docker 可选Docker 三服务(memory-core + memory-hub + proxy)一键脚本;Node ≥ 22.16
LLM 依赖核心功能零 API:本地嵌入模型(embeddinggemma-300m)即可跑;rerank 才可选接 LLM必须配置两组 LLM 参数(记忆提炼 + 代理转发)——数据要过模型
存储ChromaDB 默认,Milvus/Qdrant/pgvector/SQLite 可插拔未明示底层库(TencentDB 品牌暗示云数据库体系),向量 + 图结构
治理能力基本没有(个人工具取向)核心卖点:四档可见性(private/team/restricted/agent)+ ACL + 版本/状态/装备管理 + 审查共享流
超出"记忆"的能力Agent 日记、多 Agent 各自一翼Skill 技能沉淀(带验证规则)、LLM-Wiki 文档知识化、CodeGraph 代码图谱与影响面分析

📈 基准与证据质量

MemPalace:学术基准全家桶

  • LongMemEval R@5 96.6%(零 API)→ Hybrid 98.4% → rerank ≥99%
  • LoCoMo R@10 88.9% / ConvoMem 92.9% / MemBench(ACL 2025)80.3%
  • 逐题结果文件提交仓库,可复现
  • 诚实性声明:拒绝展示 100%、拒绝对 Mem0/Zep 做不对等对比

腾讯:单一基准,但数字敢给绝对值

  • PersonaMem:48% → 76%(相对 +59%)
  • 只挂了这一个基准,覆盖广度远不如 MemPalace
  • 加分项:展示的是绝对值而非只吹相对提升,态度算诚实
  • 减分项:未见结果文件/复现命令入库
🍉 一个值得玩味的发现:腾讯这个仓库是"组装式创新"——其 CodeGraph 模块直接使用了 colbymchenry/codegraph 的代码(没错,就是本系列第一期对比的那位主角),Skill 资产管理则基于 Nous Research 的 hermes-agent 优化而来。站在开源肩膀上做企业级治理层,本身无可厚非(均有致谢),但意味着其核心差异化在"治理面板 + 资产模型",而非底层技术自研。

⚠️ 风险雷达

腾讯 · License 疑点:README 自称 MIT,但 GitHub API 识别为 Other / NOASSERTION——说明 license 文件不是标准 MIT 文本。商用前务必人工核对 LICENSE 文件全文,别只看 README。
腾讯 · 仓库工程痕迹粗糙:默认分支居然是 feat/server_team(feature 分支当主分支),当前分支可见 commits 仅 6 个(squash 导入,真实开发历史不可见),README 里 clone 地址还指向另一个组织(Tencent/ 而非 TencentCloud/)。典型的"内部项目匆忙开源"痕迹。
腾讯 · Issue 积压率高:14k star 对应 512 个 open issues(3.6%),MemPalace 是 680/58k(1.2%)。官方承诺 24 小时响应,但数字说明带宽吃紧。另外其 CodeGraph 目前只支持公开 HTTPS 仓库,私有代码库场景尚未就绪。
MemPalace · 增长熄火:8 天只涨 266 星,爆红期结束;bus factor ≈ 1(igorls 主导)的老问题仍在;fork 比 12.9% 依旧偏高;还得继续提防假冒官网(认准 github.com/MemPalace/mempalace 与 PyPI 官方包)。
共同的隐私分野:MemPalace 核心功能可纯本地零 API 跑完;腾讯方案的记忆蒸馏依赖 LLM,意味着对话数据要过模型——数据敏感场景部署前先想清楚模型接的是谁。
值得肯定:两家都开源了真实的基准数字且没吹 100%;腾讯的中英双语文档(README/INSTALL/CONTRIBUTING 全套)是大厂开源的体面;MemPalace 的多后端可插拔设计避免了供应商锁定。

🧭 选型决策树

「个人开发者,就想让自己的 Claude Code / Cursor 记事」

→ MemPalace。pip 装完即用,本地嵌入零 API,钩子自动保存,轻量无负担。

「我在搞多 Agent 团队/一人公司,要技能沉淀 + 权限治理」

→ TencentDB-Agent-Memory。Skill/Wiki/CodeGraph 四类资产 + ACL + 装备管理,这是它的设计原点,MemPalace 根本不在这个维度竞争。

「数据敏感,绝不过外部 API」

→ MemPalace(本地嵌入跑全流程);腾讯方案蒸馏必须过 LLM,除非你愿意自托管 Ollama 类模型填它的两组 LLM 配置。

「需要文档知识化 + 代码影响面分析」

→ 腾讯(Wiki + CodeGraph 开箱即用,虽然 CodeGraph 是站在 colbymchenry 肩膀上);MemPalace 不做代码图谱。

「最后的提醒」

→ 两家都只有 4 个月大。腾讯这个仓库 license、默认分支、issue 积压三个疑点建议先观望一个版本周期;MemPalace 增长熄火后更要看社区留存。生产采用都请锁版本。
